## Fixed in round 1 (code committed; SQL = `supabase/nevorai-os/academy_0006_hardening.sql`, he runs it)
1. **Online (gateway) payments could never reach the fee ledger.** `record_billing_payment` refused the service role, so the Razorpay webhook always failed. Fixed in SQL; proven locally (₹200 on a ₹500 invoice → balance ₹300, repeat call counted once, a random signed-in user still refused).
2. **`verifyClientPayment` had no owner check** (anyone signed in could mark another family's payment failed) and swallowed ledger errors, reporting a clean success when the ledger write failed. Now: only the payer, academy staff or platform admin; a failed ledger write is flagged (`ledger_pending`) and returned as `ledgerRecorded:false`.
3. **Service worker never shipped.** `/sw.js` returned 404 on the live site (built into an unserved `dist/` folder), so web push and the PWA never started. Now written to `public/` so both deploy layouts serve it; precache stays empty; cache-forever limited to hashed `/assets/`. **Needs a deploy to take effect.**
4. **WhatsApp "mock" adapter reported `delivered` in production** while sending nothing. Now fails with "WhatsApp is not connected yet, so this message was NOT sent." (`ALLOW_MOCK_DELIVERY=1` re-enables it for testing; the platform-admin Provider Sandbox needs that flag in production.)
5. **Username login had no attempt limit.** All username sign-ins come from the server's own address, so the auth service could not tell visitors apart. Added 8 tries / 10 min per username and 40 / 10 min per address.
6. **Signed-out visitors held INSERT/UPDATE/DELETE on every table** (row rules were the only guard) and could run three attendance clean-up functions (one takes the date as input). Cut down to public reads + submitting a registration; clean-ups are service-role only.
7. Silent failures surfaced: tenant onboarding (logo, price log, and the "could not suspend" case), fee-plan delete/hide.
